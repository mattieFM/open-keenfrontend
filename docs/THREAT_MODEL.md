# Threat Model

## Assets

- Master, Read, Write, Access, and Organization keys;
- Project ID and custom hosts;
- event schemas and property names;
- query bodies and results;
- raw events and extraction files;
- dashboard definitions and public keys;
- maintenance scope and audit history.

## Trust boundaries

1. user to renderer input;
2. renderer to preload bridge;
3. preload to Electron main IPC;
4. main to configured Keen service;
5. imported files to local repositories;
6. remote image hosts to dashboard viewer;
7. public viewer to restricted bearer key;
8. optional relay to upstream DNS/network.

## Primary threats and controls

| Threat | Control |
|---|---|
| XSS steals unlocked keys | no arbitrary HTML, React escaping, sanitized Markdown pipeline, CSP, no remote script/CDN |
| Key leaks in URL | Authorization header; redaction; public fragment limited to dedicated Access Key |
| Key leaks in logs/errors | no request logging; recursive redactor; request inspector built before secret injection |
| Renderer compromise reaches filesystem/Node | sandbox, context isolation, narrow preload, no nodeIntegration |
| Malicious custom host receives key | host shown and explicitly approved; HTTPS; base path confinement |
| Cross-workspace key confusion | credential IDs scoped in workspace UI; lock and leave clears selected workspace keys |
| Restricted key silently broadens to Master | explicit selector; router never performs fallback after denial |
| Ambiguous write retried | zero mutation retries; bulk item retry is explicit and item-scoped |
| Filtered delete becomes collection delete | non-empty scope assertion; URL serializer; separate whole-delete method; preview hash |
| Remote image tracks viewers | HTTPS only, no-referrer, visible disclosure, load failure state |
| Imported dashboard executes content | size limit, JSON parse, schema-shaped model, Markdown rather than raw HTML, URL validation |
| Service worker stores API data | no service worker is registered; future policy limits cache to application shell |
| Dashboard service contract changes | adapter/feature flag/local fallback/live contract suite |
| Public key overexposes tenant data | saved/cached allow-list; enforced tenant filters; policy preview; one key per dashboard |
| Relay SSRF | fixed upstream configuration, DNS resolution checks, private IP rejection, no redirects |

## Residual risks

- An unlocked desktop process can be inspected by a sufficiently privileged local attacker.
- Clipboard managers and screenshots are outside the application's full control.
- Electron DevTools are enabled in development.
- A public restricted key is visible to every public viewer.
- API semantics and Access Key option names can evolve; live contract tests are required.
- Remote dashboards may contain unknown fields or content not generated by this app.

## Assumptions

- Users possess keys lawfully and understand their project scope.
- Operating system and Electron distribution are trusted.
- Keen HTTPS endpoints and certificate validation are trusted.
- A Master user reviews generated Access Key policy before publishing.
