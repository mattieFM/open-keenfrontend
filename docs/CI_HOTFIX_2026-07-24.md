# CI hotfix — missing release self-test

**Date:** 2026-07-24

## Failure addressed

The verification job failed with:

```text
Required release helper is missing: tests/release/release-pipeline.test.mjs
```

The checkout action had completed and `package.json` plus the validator were present. The referenced file existed in the distributed ZIP but was not tracked in the checked-out commit. The exact cause was the unanchored `.gitignore` rule `release/`, which matched both the root electron-builder output directory and `tests/release/`; consequently, `git add .` silently skipped the release test. It was not caused by npm installation or by the checkout action update.

## Changes

- Anchored generated root directories in `.gitignore`, including changing `release/` to `/release/`, so source subtrees with the same name are never silently ignored.
- Moved the dependency-free release fixture from `tests/release/release-pipeline.test.mjs` to `scripts/release-pipeline-self-test.mjs` so all release pipeline implementation and validation files live together.
- Updated `package.json` and `scripts/validate-release-workflow.mjs` to use the new path.
- Added an early source-tree validation step immediately after Node setup and before runtime-library or dependency installation, so a partial commit fails immediately with a precise source error.
- Moved the resolved npm lock artifact upload directly after dependency installation. A generated lockfile is now downloadable even when a later lint, test, build, or startup check fails.
- Changed no-lock handling: branch, pull-request, and manual builds emit a notice, generate a lock, and upload it; an actual pushed `v*` release fails before installation unless a reviewed lockfile is committed.
- Changed Action validation to require a full 40-character pin, an official-action allowlist, and one consistent pin per action without duplicating exact SHAs in the validator. Dependabot can now update a reviewed Action pin without requiring an unrelated validator edit.
- Dependabot-triggered runs continue through verification and native packaging but skip GitHub Release publication, which would fail under Dependabot's read-only token. The merge push publishes normally.
- Added `.gitignore` regression validation and a Git index check: when validation runs inside a work tree, every required release file must be tracked, not merely present on disk. These catch the exact failure before push.

## Required commit check

Before pushing, verify that Git tracks the release support files:

```bash
git ls-files --error-unmatch \
  scripts/validate-release-workflow.mjs \
  scripts/release-pipeline-self-test.mjs \
  scripts/prepare-ci-release.mjs \
  .github/workflows/electron-build-release.yml
```

Then run:

```bash
npm run validate:release-workflow
npm run test:release
```
